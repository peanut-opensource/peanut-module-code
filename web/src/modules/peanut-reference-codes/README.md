# 基础字典的正式复用入口

## 平台默认字典与租户覆盖（本模块开发候选，尚未发行）

模块拥有两类普通字典原始数据：部署级 `pa_system_dict_type/data`，以及按可信 Tenant Scope 隔离的 `pa_dict_type/data`。平台值身份由 `type_code + value` 决定，名称不是主键。新管理入口为 `/system/dictionary-catalog`，只查看平台定义，并将租户使用模式、隐藏与显示名称覆盖写入独立的 `pa_dict_type_policy` 和 `pa_dict_entry_override`；原 `/system/dict` 继续管理租户自有类型和新增值。两条入口互相链接，但平台原始记录不暴露为租户写操作。

- `system`：只返回启用的平台值，租户值不参与；平台标记 `tenant_mode=system` 时不可解除平台锁定。
- `extend`（平台默认）：系统值在前、租户新增值在后；相同 `value` 系统值优先；租户可按系统值隐藏或改显示名称，不能改 `value`；隐藏系统值不会由租户同值记录重新出现。
- `tenant`：只读当前租户自己的启用项。没有平台类型时默认此模式，不必创建空的策略记录。
- 平台类型停用时，两侧业务选项均不返回；租户类型停用时，其所有自定义项不返回。单个选项停用同样不返回。
- 租户模式、单项覆盖记录随数据库保留；更新平台原始名称会在没有租户覆盖的地方生效，有覆盖的地方继续按租户名称显示。平台不允许租户改原始 `value` 或批量复制平台选项到租户表。

普通选项读取仍复用 `DictionaryQuery::enabledByType` 和既有 `GET /adminapi/dict/data/byType`，新增配置 API 为 `/adminapi/api/v1/dictionary-catalog` 系列，全部由模块权限和当前登录租户控制。设置项用 `peanut.reference-codes.manage`，读用 `peanut.reference-codes.read`，不能从请求体选择 `tenant_id`。

新迁移先检测租户有效字典值重复，阻断带有重复数据的实例并给出涉及租户和类型，而不是静默丢弃数据；新增有效值唯一索引不限制软删除历史。生产数据库不能直接重置以绕过冲突。

本模块不随安装填充虚构的业务预置值。平台或业务模块需要提供有产品定义的系统类型和选项，经原生安装/升级迁移向系统字典表写入；目前初始 `baseline-data.sql` 没有通用平台值。实际预置清单、升级幂等、卸载/退役保护与真实浏览器/多租户回归仍须在正式发行前审定并测试。此段源码与静态检查不代表已经完成发行或下游采用。

模块标识为 `peanut.reference-codes`。前端包导出宿主路由贡献，字典目录页面使用上述租户字典 API。
