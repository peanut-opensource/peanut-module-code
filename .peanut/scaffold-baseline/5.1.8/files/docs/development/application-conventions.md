# 应用开发约定

状态：已生效。APP-R01—APP-R17 与软删除共同构成当前应用开发合同。目标是“声明差异、复用流程”，不是新增 17 套框架；实现状态以实际源码、生成物和验证结果为准。

## 1. 已确认：通过 xxClass 声明，通过 xx 使用

Controller 在受信源码中声明 `protected string $ordersClass = OrderQueries::class`，通过 `$this->orders` 取得对应对象；不限 service/model 名字。类声明、对象访问、订单/仓库等业务参数分开。

```php
/** @property-read OrderQueries $orders 订单公开查询服务。 */
class ExampleController extends BaseAdminController
{
    protected string $ordersClass = OrderQueries::class;
    // $this->orders 按声明解析；示例 OrderQueries 需由业务模块定义并绑定。
}
```

复用当前 App 容器，接口必须有正式绑定；跨模块须有依赖和公开合同。只解析显式允许的受保护声明，核验类型、继承覆盖、保留名和冲突，不扫描执行任意 *Class 字符串，不接受请求/租户配置传类名。App、Request、context 不能被业务声明覆盖；未知/缺绑定/冲突明确报错，不伪造默认身份。只读访问不能改写上下文；身份由正式入口建立并在 finally 恢复。

业务服务继续构造注入；控制器装配统一隐藏，授权/事务/输入输出不隐藏。新增共享依赖优先显式 xxClass；方法注入及有明确用途的 Getter/构造注入仍合法，不复制服务或新建容器。解析、类型提示、生成器与正常/拒绝测试一起交付。

## 2. APP-R01—APP-R17

### APP-R01：统一简单 CRUD 合同
决策状态：已生效。
统一列表、详情、新增、修改、删除的参数/结果/错误；Controller 声明服务、校验器和开放动作，减少分类等重复适配。支持[软删除](#3-软删除)；删除、归档、状态变更分开。旧 URL/响应保持；订单、支付、库存使用业务用例，不套万能 save。

### APP-R02：分开输入校验与可写字段
决策状态：已生效。
按动作区分原始输入、验证结果、允许字段和类型转换。多传 tenant_id、余额、创建者不能随验证成功写入；未知字段拒绝/剔除、null/空串/缺字段语义逐接口固定；内部调用仍守业务不变量。先保护写入口，不把验证结果误当自动过滤后的数组。

### APP-R03：统一列表查询与公开输出
决策状态：已生效。
复用分页/筛选/排序/关联摘要/公开响应，只接受声明字段与操作符；列表和导出共用获准查询范围。复用 ORM/Scope，分页有界，不提供任意表查询或直接输出完整 ORM；原输出合同受迁移保护。

### APP-R04：对象生命周期约定
决策状态：已生效。
服务从当前 App 惰性取得；无状态服务可按适用容器生命周期复用，不固化人员/租户快照。Model 在一次操作内保持同一实例，新记录/新操作显式新建或重置，不跨请求共享记录状态；Validator 每次使用干净实例，Query 每次从清晰初态开始。上下文按请求/任务，SSR 按请求隔离；测试连续校验、连续保存及身份切换，不把所有对象套同一缓存。

### APP-R05：业务动作统一登记
决策状态：已生效。
路由、模块、权限、按钮和诊断共用稳定动作及定义，如 article.edit。现行适用入口统一接入既有路由/授权；中间件、公开服务、Scope 各守检查边界，动作登记不授予权限，不造第二路由引擎。

### APP-R06：事务、钩子和事件命名
决策状态：已生效。
区分输入前处理、事务内、提交后、可靠异步，明确失败传播/回滚/重试。afterSave 不混用提交前后语义；不把支付/库存流程藏进模型监听器，不声称数据库可撤销外部副作用。先统一语义与样板，不全仓事件化。

### APP-R07：前端列表和表单公共能力
决策状态：已生效。
复用 Vue composable/现有 UI 的分页、加载、取消、错误和提交状态；页面声明列、筛选、布局与模块 SDK。业务页面/状态留 Code；请求取消、租户切换、SSR 状态有清理隔离。与后端合同同批迁移全部适用页面，不造万能低代码语言。

### APP-R08：统一文件引用入口
决策状态：已生效。
声明用途、数量、格式和引用；现有文件模块统一上传/访问/临时文件/补偿。头像、封面、附件复用；保存稳定引用，不存临时签名 URL，保留旧存储绑定和权限。

受控资源只持久化 `file_[32 位十六进制]`，拒绝外部媒体地址、临时交付链接和物理存储路径。读取通过 `FileAccess::resolve(TenantContext, fileKey, operation, documentId?, variantKey?, viewerAdapterId?)` 或登录后的 `POST /adminapi/api/v1/files/resolve`，操作为 `preview`、`download_original`、`manage`。File 每次签发和交付均复核持久 session、当前成员授权、模块状态、资源状态与修订；预览不授予原件下载。没有下载权时只交付已登记且核验真实字节的衍生内容，没有适配工具或衍生能力则返回 `preview_unavailable`。File 只消费 Content Tools 的显式选择合同。

Document 通过其正式 provider 贡献 `FileDocumentReferencePolicy`；缺少 provider 时包括空引用集合在内一律拒绝。`FileReferenceCommands::replaceDocumentReferences` 必须由 owner 的业务保存事务调用，provider 在同一 ThinkPHP 连接中锁定、核权并返回当前持久引用；File 索引与该事务一起提交，保护资源删除。文档授权仅可继承当前获准引用的预览，涉密附件、原件下载和管理均需要独立 File 权限。前端薄封装 `createFileContentCallbacks` 每次解析短时地址，不把地址保存为正文。

应用交付地址的撤权不证明旧物理源站或 CDN 已撤销；公开空间迁移与物理撤销由 File 的资源阶段一单独验证。当前衍生绑定核验图像真实尺寸/MIME/SHA-256；尚无生产衍生处理器的格式明确不可预览，不以原件地址冒充衍生预览。

同步 XLSX 导出在创建临时文件或对象前通过 `FileStorage::requireOriginalDownloadPermission` 复核可信当前 session、File 模块和独立原件下载权限；`export.xlsx` 存储后再按当前对象授权签发 `download_original` 地址。存储后的授权或返回准备失败由 File 内部同次新上传凭证补偿，保留原错误；未知物理删除结果保持不可交付并记录待处理。主动或未知 MIME（包括 HTML、SVG）在公开和私有交付均为附件；只有已核验的安全图像/音视频 MIME 可内联。

### APP-R09：统一服务配置入口
决策状态：已生效。
声明提供方与配置，通过[四种绑定策略](../architecture/service-bindings.md)解析有效配置/秘密引用。存储/短信不各自猜继承；不下发平台密钥，不因自定义失败静默借用平台付费渠道；复用现有 Service Binding。

### APP-R10：缓存声明与失效
决策状态：已生效。
声明内容、隔离维度、期限和失效条件；公共/受限缓存按数据语义分别处理，不机械添加同一 tenant_id。受限结果先授权再读取，键含影响输出的范围/授权修订；先整理实际缓存，不强制全部查询缓存。

### APP-R11：任务声明与执行
决策状态：已生效。
声明稳定输入、处理者、权限、重试和结果；统一上下文恢复/领取/续租/失败。复用现有任务系统，导出/通知只写业务差异；按批次和交付边界检查授权与租约，外部操作另有防重复和核对，不造第二队列。

### APP-R12：错误与日志入口
决策状态：已生效。
稳定业务错误码＋结构化上下文，由现有异常/响应工厂统一 HTTP 映射、中文提示、追踪和脱敏。区分成功/失败/未知；全部现行适用入口按开发规范 v1 同批对齐，不长期并存新旧规则；不改既有成功合同来迁就测试。

### APP-R13：通用数据格式
决策状态：已生效。
明确时间/时区、金额/数量精度、枚举和 JSON 序列化；沿用 UTC 与领域精度，不用浮点结算，不强制所有数值两位小数，不自动修改历史金额。先规范类型，数据迁移另按保护流程。

### APP-R14：模块声明统一消费
决策状态：已生效。
开发者中心、Provider、依赖、路由和打包消费同一正式定义；沿用 module.json/Composer/Plugin。下游业务默认放入自己的 Module，跨 Module 及对 Core 的调用使用已声明的公开契约，不以修改 Core 内部实现承载单一业务。发现、安装、租户开通、人员授权仍分开，不造第二 manifest，不猜目录执行。

### APP-R15：生成器、类型和文档同步
决策状态：已生效。
生成普通可读代码、声明、准确类型/跳转、基础测试和接口资料；与 xxClass 同批验证。保留可编辑扩展区，检查真实加载和消费者；生成不等于业务/测试完成，不造复杂 DSL，不继续生成过时样板。

### APP-R16：定制扩展与升级
决策状态：已生效。
分开上游受管区、客户自定义及秘密；独立升级入口复用现有差异/冲突和恢复能力，install.php 仅用于首次安装。公共底座须接收上游修复，不把整个 server/app 或前端都归为客户自有。Web界面扩展合同和Code宿主接入状态见[Core能力与应用覆盖](../architecture/core-capabilities-and-application-overrides.md)；`web/src/peanut.overrides.ts` 属 `app-owned`，沿模板inventory与baseline处理。更新保护客户代码，但“文件未冲突”不等于业务兼容：plan 在 apply 前检查客户 Module 的目标 Kernel 约束和可静态确定的 Core 类/静态方法引用，不兼容先报告、修正 Module 后重跑计划，不自动改业务源码。回退代码不证明数据库/外部副作用已恢复，真实客户操作另需授权，不造第二升级引擎。

### APP-R17：可解释诊断与验收
决策状态：已生效。
显示未安装/未开通/未授权/未运行/未验证的具体原因、服务提供者和任务失败；接入真实状态，不从配置推断测试通过。仅展示获准信息，保护其他租户和秘密，沿用开发者中心维护现有适用范围；未实现能力明确标记，不将路线图当成运行事实。

## 3. 软删除

必须支持软删除；不等于所有表强制新增同一字段。业务模块声明删除模式/删除字段并优先复用当前 ThinkORM 能力，保留既有数据语义；未明确的表不擅自迁移。

- 启用软删除的对象：普通读取/列表/计数/导出/关联默认排除已删项；查看已删数据、恢复、永久删除是显式动作，仍核验模块、人员、租户 Scope 与对象归属，不因 withTrashed 等读取方式关闭其他过滤。
- 恢复先检查唯一性、关联及业务状态冲突，不覆盖同名新记录、不跨租户恢复；批量操作明确全部/部分成功，重复请求有稳定结果。
- 软删不自动物理删除关联记录或外部文件；文件引用、保留期限、永久清理和审计按所属模块合同执行。停用/归档/撤单/退款不等于删除，不给账本、支付事实套通用删除。
- 生成器/管理界面只开放明确允许的删除、回收查看、恢复、永久删除能力；没有配置不会自动授权或暴露路由。
- 验证：默认不可见、授权查看/恢复、唯一冲突、同租户/跨租户拒绝、关联/计数/导出一致、重复/批量结果及外部文件不被意外清除。文档批准不证明全项目已具备这些实现。

## 4. 实施次序与归属

每项交付包括开发者写法、执行机制、类型/生成器、正常与失败检查和退出默认流程的方式。现有接口按受控迁移对齐，不用兼容别名或删除断言掩盖偏差。

Controller/CRUD/HTTP 便利在 Code 公共应用层；业务在模块；无业务客户端在 Web Core；技术 Scope/模块协议在 PHP Core。复用已有框架，适配旧公开合同，不全仓静态化。

## 5. 租户数据与生命周期

共享库的业务表按租户行隔离，唯一约束和关联同时验证租户归属；平台或技术数据不机械添加tenant_id。事务、外部副作用及时间/数量精度沿[规范第6节](standard.md#6-输入数据事务与文件)，软删除沿[第3节](#3-软删除)，不在各模块维护另一套定义，也不借规范迁移批量修改历史金额或退款终态。

租户暂停或归档后停止新普通业务和任务，仅保留明确授权的恢复、导出等入口；卸载代码与删除数据分开批准。删除、迁移、备份及恢复必须明确操作人、范围、计划与审计。开发检查只使用独占的合成数据，真实客户或生产操作另行批准。

Standalone与SaaS共用租户业务结构，SaaS可以有额外运营数据。将默认租户转入同一实例SaaS之前须备份、预检并授权，不自动导入其他客户；反向转换仅在没有其他租户数据和有效租户等明确条件下支持。多租户拆成独立实例需要单独迁移合同，旧tenantless数据需要人工迁移方案；隐藏界面或修改环境值不等于数据转换完成。
