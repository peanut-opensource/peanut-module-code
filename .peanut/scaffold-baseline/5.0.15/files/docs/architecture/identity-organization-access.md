# 身份、组织与执行信息

已生效设计。账号、会话与执行上下文遵守[开发规范](../development/standard.md)，Scope 见[范围专题](tenant-modules-and-data-scopes.md)；实现与验收以实际源码和运行结果为准。

管理端需要同时投影多个动作时，调用 `AdminAuthorizationQuery::decisions($tenantContext, $permissionKeys)`，以权限键为索引读取 `PermissionDecision`。该入口在一次调用内读取当前人员、登记及许可上限和角色授权；不要求调用方先读取 principal，也不跨调用或请求保留权限快照。单项 `decide` 合同继续保留。Identity 的许可修订投影在同一调用链内复用已读取的许可与模块清单，独立调用仍重新读取当前状态和有效期。

## 1. 四个概念

身份回答谁调用（人/设备/程序，可并行）；租户回答独立客户的数据空间；业务对象回答操作什么；角色＋范围回答允许什么动作/数据。Instance 是部署，Platform 是当前实例运营范围，不自动跨实例/租户。缺租户不是全租户权限。

平台租户治理在同一 HTTP 请求内直接传递认证入口建立的 `PlatformOperatorContext`，不在服务适配层重新解析 bearer 或建立另一套身份端口。业务事务仍由 Identity 加锁核对当前 operator 状态；请求外或新的执行边界须重新认证。

## 2. 人员、终端、程序与业务关系

人员可有平台、租户员工、客户、合作方身份及多个租户关系；认证边界中的全局账号不等于全产品/实例共享身份。共用认证机制、安全域/会话独立，显式验证后关联，不按电话/邮箱/姓名合并；关联不串权限，保留历史 ID。客户/供应商档案可无登录账号，联系人登录不自动开户或获员工权。

业务主体=个人/组织；客户/供应商/合作方是可并存的业务关系，不是权限角色。平台支持/代运营须有目标、来源、期限、范围、撤销与审计，不天然进入客户业务。

## 3. 部门、岗位、角色和数据范围

部门/组织单元表达归属与分工，岗位表达职责，角色表达动作，范围绑定这份授权的对象。部门管理某资源不代表部门成员都能操作；岗位映射角色必须可追溯并定义变动/撤销，不能按名称判权。

管理员新增、编辑通过 `jobs_id` 保存本租户的成员岗位关系，与成员资料、部门、角色及状态同一事务提交。编辑省略该字段保留原关联，显式空数组清空；详情和列表返回实际 `jobs_id`、`jobs_name`。新关联只接受本租户启用且未删除的岗位，已有岗位停用后保留关联；岗位被成员使用时删除返回 409，须先解除关联。岗位关联本身不授予角色或动作权限。

独立权限包表达业务动作，由 Identity 统一维护现有 `pa_permission` 的稳定 key、名称、来源和受众。来源分为系统 `system`、模块 `module` 和实例自建 `custom`；系统及模块定义由源码维护，实例自建定义通过平台后台创建、改名及退役，普通模块同步不覆盖自建定义。不按菜单、按钮或客户端复制定义。权限包与 API 是多对多关联：一个权限包可包含多个 API，同一 API 可被多个权限包复用。单个菜单或按钮的 `perms` 引用一个权限包 key，角色授予同一安全域内的权限包，各客户端复用同一业务授权。

角色管理的“分配权限”窗口按独立权限包配置授权。`GET /adminapi/role/permissions` 返回角色稳定 key、当前修订和完整 `permission_keys`；`GET /adminapi/role/permissions/catalog` 分页返回当前租户可分配的权限包名称、键及所属模块；`PUT /adminapi/role/permissions` 使用 `role_id`、`expected_revision`、`permission_keys` 原子替换。读取角色、读取目录和分配分别使用 `core.role.read`、`core.permission.read`、`core.role.permission.assign`。保存携带读取到的角色修订；缺失修订返回 428、冲突返回 412，不能自动读取新修订后重试。内置 owner 权限仍禁止修改，平台、退役或模块不可用权限包仍由 Identity 拒绝分配。

权限包定义和 API 关联的管理入口是平台“平台角色与权限”中的“独立权限包与 API 关联”，读取要求 `platform.permission.read`，维护要求 `platform.permission.api.manage`。定义编辑仅限实例自建包；系统及模块定义只读，但其 API 关联可作实例配置。租户只授权已有可用包并只读查看关联，不能创建定义或覆盖实例配置。保存关联使用权限包自己的 `expected_revision`，与角色授权修订独立；显式空 `api_ids` 表示清空该权限包的 API 关联，后续同步不会重新填入源码默认项，但关联修改或自建包退役不能移除管理界面六个必要 API 的最后一个有效平台权限包关联。尚未进行实例配置的权限包跟随源码默认关联的增删，有效关联改变时更新修订。接口字段及该例外的精确范围见 [API 合同](../public/api-and-sdk.md#独立权限包与-api-关联)。

菜单与按钮管理只引用已有权限包。自建页面菜单可指向已登记的静态业务页面，受管菜单也可在保留源码身份与默认定义的同时显式引用同域有效的已有权限包（system/module/custom）；该实例引用替代默认菜单门槛，清空恢复源码默认，模块同步保留实例引用。按钮沿用 `A` 类型，以 `paths` 保存该页动作标识，由父级 `C` 类型菜单的 `paths` 限定所属页面。用户信息的 `action_bindings` 显式返回页面、动作与权限包的配置关系，前端仅在当前页面按该配置判断按钮权限。API 关联不会把源码默认动作 key 自动加入用户权限；持有 API 关联包也不等于取得另一页同名动作或额外前置权限。

MT 实例的菜单、按钮引用由平台通过 `GET /platformapi/permission/menus` 和 `PUT /platformapi/permission/menus/binding` 配置，复用 `platform.permission.read`、`platform.permission.api.manage`，保存记录平台审计。该入口只维护已有页面与按钮的权限引用，以及尚为空的按钮动作标识；不提供完整菜单增删改，也不改变页面路径、源码身份或模块归属。租户角色授权不能用来修改实例全局菜单配置；原管理端菜单编辑仍限 ST。字段及修订合同见 [API 合同](../public/api-and-sdk.md#实例菜单与按钮引用)。

受保护 API 按实际匹配路由确定登记身份，调用者具有任一关联权限包可满足该 API 的主要动作授权，同时必须满足源码声明的全部前置权限；没有有效关联的受保护 API 拒绝访问。关联管理只替换主要动作权限，不改写 `prerequisite_permission_keys`。现有平台运维的日志、诊断、升级和模块操作仍分别要求 `platform.ops.read` 与其专属动作权限同时成立；将 API 关联到其他权限包后，`platform.ops.read` 仍须独立取得，主要动作的本次请求授权记录不能满足它。只允许关联同一 tenant/platform 受众的受保护 API，公开、仅认证及其他上下文入口的模式仍由源码控制。API 所属模块必须独立满足已安装及租户开通要求，不能因另一个模块的权限包引用它而绕过。身份、租户、对象授权和数据 Scope 继续由原业务入口核验；`resource_operation_permission` 仍属于资源操作的数据授权合同，不作为 API 关联表。

多客户端复用指使用同一身份与授权域的客户端可以引用同一权限包，不代表各安全域合并。本次 API 关联管理覆盖 tenant/platform 受保护入口；会员/用户中心、公开及安装入口保留其原认证和业务授权模式，目录中可发现它们不等于已经将其接入角色权限包。

例：张三“审核＋S1”“查看＋S2”，不能组合成“审核 S1/S2”。保留授权来源与范围；同动作允许按范围并集，同对象明确拒绝优先。临时/继承/撤销/缓存按统一授权机制，不留隐式权限。

租户管理员通过 `GET /adminapi/role/data-policy/catalog` 分页查看当前已启用模块的资源操作；指定 `resource_key`、`operation` 时返回该操作允许的条件及目标类型。`GET /adminapi/role/data-policy` 使用 `role_id`、`resource_key`、`operation` 读取一份角色策略；`PUT` 同一路径提交这三个定位字段和 `policy`。读取与修改分别要求现有 `core.role.data-policy.read`、`core.role.data-policy.manage`，租户及操作者只来自当前真实会话。

首次配置使用空 `expected_revision`；修改已有策略必须带上读取到的修订，缺失返回 428、过期返回 412。策略只接受登记条件、合法目标、状态、期限及原因；角色动作权限不会自动产生数据范围。配置和办理权限分别验证，不能用租户 owner 绕过普通办理人的对象范围。

## 4. 人员和终端的共同处理

| 场景 | 身份与限制 |
| --- | --- |
| 网页后台 | 员工；普通浏览器不强制独立设备凭据 |
| 人工 POS | 收银员＋登记设备；同时受人和设备范围约束，换班不继承上一人 |
| 自助收银 | 可匿名/登录顾客＋受限设备；按适用的各自权限 |
| AI 代人执行 | 实际程序＋被代表人；明确动作/租户/对象/期限/撤销，不复制万能员工 Token |
| 自动同步 | 服务账号自身授权，不虚构在线人、不永久绑定离职员工会话 |

并非每次同时认证两种主体；权限不超过适用的人/程序/委托上限。记录实际执行者、客户端/设备、被代表者。

## 5. 令牌、请求上下文、业务参数分开

| 信息 | 归属 |
| --- | --- |
| 人/程序、可信设备、租户关联 | 验证后的 Token 或服务端会话；不必全写进 Token |
| Token 编号/签发/过期时间 | 凭证生命周期 |
| 请求编号/服务端接收时间/追踪 | 本次执行上下文 |
| 单据、仓库/门店、源仓/目标仓、数量 | 业务参数 |
| 本次可操作范围 | 服务端核验动作、对象归属与授权所得 |

只设统一请求/执行上下文，不平行建万能业务上下文；模块可封装已验证业务输入。令牌编号≠请求编号，签发时间≠请求时间；登录不是永久授权。设备仅准 W1、参数选择 W2 时拒绝；同租户选仓不必换 Token，切租户须重验授权。G 获准读 A/B 时仍是 G 身份，不切成来源员工。

每请求/任务建范围并 finally 恢复，worker 不沿用上次身份/事务，任务不保存秘密 Token。具体读取器可复用，身份快照不能跨请求缓存。

收货例：验证凭证→建立本次上下文→校验单据/仓库/数量→在租户范围读取→检查动作与仓库权限→检查单据既定仓库→采购公开服务处理→审计关联人/机/单据/仓库。仓库参数不能覆盖单据业务约束。

## 6. 业务工作区与代码工作区

业务工作区=客户端内围绕工作组合的菜单、页面、动作、布局和默认选择；也可由独立客户端承载，不默认等于客户端/子租户，更不产生权限。例：租户后台→仓储工作区→本页 W1。偏好不是授权，多标签分别选 W1/W2，逐请求提交/验证，不以全局“当前仓库”串操作。

代码工作区仅指源码检出的开发目录。未来需要独立成员或数据的协作空间，由业务模块另行建模，不从界面工作区推导。

## 7. 业务主体、资源与关系数据

主体是业务对象的一类，门店/仓库为资源，货架/库位为内部位置，订单为单据；组织树、业务关系和集团关系不是一棵授权树。当前不设租户内经营公司或隐式子租户。

关系示意：`(tenant_id,store_id)` 与 `shelves.store_id`；`(tenant_id,warehouse_id)` 与 `locations.warehouse_id`；需要时模块维护 `party + business_relation`。用普通表/关联，不每资源建表；外键/唯一约束核租户一致。跨模块走公开服务；共用客户/供应主体模块属后续业务取舍，不预建万能资源表或强制公司层。

## 8. 统一资源引用与审计

公共引用为租户＋登记对象类型＋ID，不携 ORM/任意表名/类名，不授访问权。所属模块的受控摘要服务先授权再查当前资料。

审计保存当时可读摘要及必要前后变化，不能拿当前名称冒充历史，原对象删除后仍应可解释。调拨可同时关联单据、源 W1、目标 S1；只留必要信息，排除秘密/过量个人资料，脱敏并限制读取。

## 9. 验证

覆盖离职/角色撤销、设备禁用、委托过期、租户暂停、模块停用、伪造 ID/跨租户、双标签切换、调拨两端权限、删除后审计可读性。设计列出不等于测试已经执行。

## 10. 会话、敏感操作与撤销

平台、员工、客户和合作方共用认证、限流、撤销及审计基础，但凭据用途与会话属于各自安全域。外部身份按签发方、应用/安全域和主体识别；员工可关联多个租户，客户资料、订单、余额和标签仍按租户隔离。网站与应用可共用本租户客户身份，但会话按客户端签发。

| 操作 | 撤销范围 |
| --- | --- |
| 退出当前端 | 当前会话，不以清空浏览器状态代替服务端撤销 |
| 全部退出或安全改密 | 相应账号安全域内的会话，不越过其他独立身份 |
| 员工离职 | 该租户成员访问，不删除其其他租户关系或客户身份 |
| 角色、模块或委托失效 | 新请求核权威状态；已完成业务不追溯撤销，在途任务按范围专题处理 |

高权限入口要求额外认证，敏感操作按合同再认证；不接受顾客令牌冒充员工或平台身份，租户管理员不能重置其他安全域凭据。复用既有认证实现，不自造密码学。

浏览器优先内存访问凭证配受保护刷新会话，Secure、HttpOnly、SameSite 与 CSRF 防护一起设计；刷新轮换和重放拒绝须验证。移动端沿稳定适配器使用可用安全存储，不把普通本地存储描述成秘密保险箱。这里给出已批准的开发约束，不因正文补齐声称现行所有入口或终端都已通过验证。

租户管理端刷新入口要求受保护刷新 cookie 与 `Authorization: Bearer <access_token>` 同时提供。access token 可以过期或已轮换，但其存储记录必须与刷新凭据属于同一会话和客户端，并属于请求 Host 绑定的租户；身份不匹配时在轮换前拒绝刷新，不轮换另一会话。Web 请求记录发起会话代际，刷新、重试和异步退出只作用于该身份；同一会话刷新不改变代际，登录、切租户和退出的开始与提交各自形成边界。同一页面写刷新 cookie 的请求按顺序执行；跨标签页凭据变化通过本地存储观测使旧请求失效，迟到响应不得以新身份重放旧请求。

浏览器刷新 cookie 的名称由 audience/client 原有 `__Host-` 前缀与精确 access token 的 SHA-256 组成；摘要只用于选择 cookie，授权仍由认证服务校验。应用宿主使用 ThinkPHP 原生 Cookie/Response 保持 Secure、HttpOnly、SameSite=Lax 与 Path=/。refresh 只删除请求旧令牌对应名称并签发新令牌对应名称，logout 只删除请求对应名称；登录和租户选择仅清理传入请求已观察到的本客户端名称。这样即使另一标签页已登录，浏览器随后应用旧响应的 Set-Cookie 也不能覆盖或删除新令牌对应 cookie。客户端的旧响应提交守卫与这项服务端名称政策分别保护界面状态和浏览器 cookie；JavaScript 无法阻止浏览器应用迟到响应头，不能仅靠前端守卫证明 cookie 隔离。动态名称无法由 OpenAPI 固定 cookie name 表达，合同通过 Bearer scheme 和描述声明选择政策。

## 11. 宿主调用身份能力的现行示例

租户入口域名由 Identity 的 `Platform\Application\TenantEntryBindingAdminService` 管理。控制器保留 HTTP 输入／输出适配，传入同一个已验证平台上下文；所属用例继续检查权限、活动租户、域名与客户端约束、绑定冲突并在同一事务记录审计。类公开不代表允许调用者直接修改绑定表。

多租户管理入口只根据 Identity 数据库中的活动 `admin-web` 域名绑定识别租户，包括公共/default 租户；不配置额外管理域名允许列表。平台入口仍由 `PLATFORM_HOSTS` 单独限定，不能作为租户管理入口。管理端匿名品牌使用 `/adminapi/config/brand`，按同一绑定读取品牌与租户名称。多租户安装不会自动把域名绑定到初始租户，须由平台通过既有域名绑定管理入口登记。登录按绑定租户验证账号成员关系，后续请求继续核对会话租户、成员状态和权限；域名或请求参数不能授予身份。

一个管理域名对应一个租户。同一租户的多个成员均可在该入口登录；同一账号属于多个租户时，应访问目标租户的绑定域名登录。管理界面不在已绑定入口提供跨租户选择或切换，后端也拒绝绑定冲突；当前没有跨域会话转移或自动跳转。登录后品牌来自 `/adminapi/user/info` 的已认证租户上下文，退出时同步重置。会员端 `/api/index/config` 与 `/api/pc/config` 的内容、名称均来自同一个 `member-api` Host 上下文；未绑定入口继续拒绝，不跨客户端借用管理绑定。开发代理须保留浏览器请求 Host，使后端沿同一 DB 绑定路径识别租户。

所有者邀请的创建、重发、撤销、查询和接受由 Identity 的 `Invitation` 用例维护；邀请表、账号、凭据、成员及角色属于同一身份业务。管理用例只接收同一个已验证 Core `PlatformContext` 并使用原生平台授权器；HTTP 包装上下文只留在控制器，不能把宿主会话服务重新变成模块依赖。`OwnerInvitationDeliveryPort` 是可信投递适配器，`TenantOwnerAdminProvisioner` 是已确认所有者后的应用初始化接口，宿主负责各自实现与绑定，不把数据库对象作为接口。原始令牌只交给既定投递或显式允许的人工交付方式，不在持久化、调试或普通日志中保存明文；重新发送和接受继续失效旧令牌，既有账号密码不得被邀请流程覆盖。

产品模块模板仅用 `AdminDirectoryQuery::profileTenantsForUpdate` 选择明确指定的活动租户，在调用方原事务内执行锁定读取；随后仍必须核对完整、精确的租户编号集合。查询结果只含编号与代码，不是开通模块或取得租户业务权限的凭据。
